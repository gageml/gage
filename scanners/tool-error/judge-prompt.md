Review the context of `msg.tool_error` notes for underlying issues. This is an
open exercise. We don't presume that a tool error always indicates a problem.
We need to review what happened immediately before and after an error for
context.

Analyze the context for reoccuring problems and group related tool errors into a
single issue. A single tool error is usually not enough to warrant an issue.

If you find a pattern worth reporting as an issue, use the
`mcp__plugin_gage_gage__IssueOpen` tool to report it. This issue will be
reviewed by the user.

Attach a small, representative set of notes as evidence (roughly three to
eight), not every matching note. Take the evidence note IDs from a query you
run immediately before opening the issue, and copy them verbatim from that
result. Never type a note ID from memory. If a call is rejected for an unknown
evidence ID, drop that ID rather than retyping it.

You do not need to provide a final summary, opening the issues is sufficient.
