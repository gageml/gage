## Hidden thinking text

When extended thinking is turned on, Claude creates thinking content
blocks where it outputs its internal reasoning. Claude incorporates
insights from this reasoning before crafting a final response.

Access to thinking text is useful when analyzing model behavior.

If session logs contain thinking messages with empty text, Gage treats
this as evidence that thinking text is hidden --- i.e. it's not being
sent by the model.

## Fix

Set `showThinkingSummaries` to `true` in `~/.claude/settings.json`:

```json
{
  "showThinkingSummaries": true
}
```

As of Claude Code v2.1.90 (April 2026), thinking summaries are no longer
generated by default in interactive sessions and this setting is
required to restore them. The harness passes `display: "summarized"` to
the API when the setting is on, so no separate per-model configuration
is available.

Restart Claude Code after changing the setting.

Thinking output is collapsed by default in the terminal client. Press
`Ctrl+O` to toggle verbose mode and view the reasoning inline.

### Cases this setting does not cover

The following are observed limitations as of 2026-08-08. They are
model-specific and version-specific, so re-check them against the linked
sources before relying on them.

Headless sessions never return thinking text. Sessions started with
`claude -p` produce empty thinking blocks on every model tested
(`claude-opus-4-8`, `claude-fable-5`, `claude-opus-5`), at every effort
level, and regardless of `showThinkingSummaries` --- including when the
setting is passed explicitly via `--settings`. `showThinkingSummaries`
applies to interactive sessions only. A headless session flagged by this
scanner has no available fix.

Opus 5 returns empty or truncated summaries. On `claude-opus-5`,
interactive sessions with `showThinkingSummaries: true` still return
mostly empty thinking blocks, and the summaries that do arrive are
frequently cut off mid-sentence. This is distinct from
`display: "omitted"` --- a truncated summary means the summary stream is
being cut short, not suppressed. `claude-opus-4-8` and `claude-fable-5`
return complete summaries reliably under the same settings, so switching
the session model is the only available workaround.

`display` defaults to `"omitted"` on Opus 5, Sonnet 5, Fable 5, Mythos
5, Opus 4.8, and Opus 4.7. On Opus 4.6, Sonnet 4.6, and earlier the
default is `"summarized"` and this issue does not arise. This list is
current as of 2026-08-08; newer models are likely to default to
`"omitted"` as well.

## Verify

To verify that thinking blocks are enabled for new sessions, create a
new session and use the model to perform a task that requires thinking.
This may take a few messages. You should see thinking blocks in your
client.

To further verify, run:

```shell
gage scan -s hidden-thinking -y
```

If your recent session contains hidden thinking text, Gage will report
the issue again.

Note that a re-scan can report the issue again even when the setting is
correct, because of the cases listed under "Cases this setting does not
cover" above. Check the model and the session entrypoint before
concluding the fix did not take.

## LLM notes

If the evidence shows `showThinkingSummaries=false|null`, that setting
should be set to `true` in `~/.claude/settings.json`. This is the only
available configuration --- there is no per-model setting and no working
CLI flag.

If the evidence shows `showThinkingSummaries=true`, the setting is not
the cause. Determine the model and whether the session was interactive
or headless, then report the applicable limitation from "Cases this
setting does not cover" rather than restating the fix the user has
already applied. Those limitations were observed on 2026-08-08 against
Claude Code v2.1.226; confirm they still hold before presenting them as
current.

Historical note: earlier guidance recommended an undocumented
`--thinking-display summarized` CLI flag as a workaround for Opus 4.7.
The harness handles this automatically when `showThinkingSummaries` is
enabled, and the flag was confirmed not to work in any case
(claude-code#56356).
